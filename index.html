OpenSSH User-Mode Setup

管理者権限なしでのSSHサーバー構築ガイド

Windows 10 / 11 対応

このガイドについて

Windowsで「管理者として実行」が許可されていない環境（学校・職場のPCや制限アカウント）でも、自分専用の独立した開発用SSHサーバー（sshd）を立ち上げるためのステップバイステップガイドです。

1. なぜ権限なしで動くのか？（全体の仕組み）

ポートを変更

標準のPort 22ではなく、一般ユーザーでも解放可能なPort 2222などのハイポートを使用します。

鍵の保存先を変更

書き込み権限がない ProgramData を避け、ユーザーフォルダや C:\fjuty 内にホスト鍵を作成します。

設定をシンプル化

管理者グループ専用設定やエラーの原因となるコメント文を排除したクリーンな設定ファイルを使います。

2. 実装手順（コマンドプロンプトで実行）

事前準備: OpenSSH-Win64 の入手

まだOpenSSHを入手していない場合は、GitHubの公式リリースから最新版のzipファイル（例: OpenSSH-Win64.zip）をダウンロードして解凍してください。

GitHub Releaseへ
1

フォルダの作成

暗号鍵用と設定保存用のフォルダを作ります。パスにスペースが含まれても崩れないよう引用符で囲みます。

mkdir C:\fjuty\keys
mkdir "%USERPROFILE%\ssh_config"
2

ホスト鍵（暗号鍵）の個別手動生成

-A オプションは管理者領域を参照してエラーになるため、パスフレーズなし（-N ""）で個別に直接指定して生成します。

C:\fjuty\OpenSSH-Win64\ssh-keygen.exe -t ed25519 -f C:\fjuty\keys\ssh_host_ed25519_key -N ""
C:\fjuty\OpenSSH-Win64\ssh-keygen.exe -t rsa -b 2048 -f C:\fjuty\keys\ssh_host_rsa_key -N ""
3

sshd_config の作成・編集

メモ帳で設定ファイルを開きます。

notepad "%USERPROFILE%\ssh_config\sshd_config"

メモ帳が開いたら、下のセクション【3. 正確な sshd_config テキスト】の内容を全選択してコピー＆ペーストし、上書き保存（Ctrl + S）して閉じます。

4

sshd サーバーの起動

作成した設定ファイルを絶対パスで指定し、デバッグモード（`-d`）で起動します。

C:\fjuty\OpenSSH-Win64\sshd.exe -f "%USERPROFILE%\ssh_config\sshd_config" -d
成功判定:
画面の最後に Server listening on 0.0.0.0 port 2222. と表示され、ログが止まれば正常に受け付け待機状態になっています。

4. 友達に質問された時の解説集（FAQ）

Q. なぜ `sshd start` や `net start sshd` が使えないの？

`net start` はWindowsの「サービス」機能を利用するためのコマンドで、管理者権限が必須です。今回のように `sshd.exe` を直接絶対パスで指定して起動することで、一般ユーザー権限のまま単体アプリとして動作させることができます。

Q. なぜ HostKey のパス区切りはスラッシュ (`/`) なの？

OpenSSHは元々UNIX系OS向けに作られており、Windows版でも設定ファイル内ではバックスラッシュ (`\`) よりもスラッシュ (`/`) を使う方がエスケープ文字のエラー（文字化けや認識失敗）を防げるためです。

Q. 実際に接続できるかテストする方法は？

別のコマンドプロンプトを開き、以下のコマンドを実行します。
ssh ユーザー名@localhost -p 2222
パスワードが求められれば正常に接続できています。
